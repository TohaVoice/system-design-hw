== 1. Инфраструктура как код (IaC)

Вся инфраструктура описывается декларативно и хранится в репозитории. Используются следующие инструменты:

* **Terraform** – для provisioning облачных ресурсов (VPC, подсети, балансировщики, кластеры Kubernetes, базы данных).
* **Kubernetes (k8s)** – для оркестрации контейнеров. Манифесты хранятся в Git и применяются через **ArgoCD** (GitOps).
* **Helm** – для упаковки и параметризации приложений.
* **Ansible** – для начальной настройки виртуальных машин (на случай если буду использоваться).

=== 1.1. Развертывание инфраструктуры

Процесс развертывания инфраструктуры:

1. **Планирование:** изменения вносятся в Terraform-модули или Kubernetes манифесты.
2. **Проверка:** запускается `terraform plan` и `kubeval` в CI/CD пайплайне.
3. **Применение:** после утверждения PR применяются изменения:
   * `terraform apply` для cloud‑ресурсов.
   * ArgoCD синхронизирует кластер с состоянием в Git.
4. **Ручное подтверждение:** для критических изменений (например, изменение сетевых политик) требуется подтверждение вручную.

=== 1.2. Развертывание системного и прикладного ПО

* **Системное ПО** (Kafka, Elasticsearch, Redis) разворачивается через операторы в Kubernetes (например, Strimzi, Elastic Cloud on Kubernetes). Конфигурация описывается в YAML.
* **Прикладное ПО** (микросервисы) упаковывается в Docker-образы, версионируется и публикуется в реестре (GHCR). Развертывание выполняется через Helm-чарты, которые устанавливаются ArgoCD.

=== Управление секретами при развертывании
* Все секреты (пароли БД, API-ключи, сертификаты, токены доступа) хранятся в **HashiCorp Vault**.
* При развертывании через ArgoCD используется **Vault Agent** или **Vault Injector**, который автоматически подставляет секреты в поды Kubernetes.
* Для доступа к Vault из CI/CD (GitHub Actions) используется временный токен, хранящийся в GitHub Secrets (только один секрет). Все остальные секреты извлекаются динамически из Vault.

=== 1.3. Обновление ПО

* **Обновления без простоя** реализуются через стратегии Kubernetes: rolling update, blue/green deployment.
* Для баз данных (PostgreSQL) используется **обновление с переключением реплик** (Patroni автоматически меняет master).
* **Схема обновления:**
  1. Новый образ собирается в CI/CD.
  2. Обновляется Helm-чарт (версия образа).
  3. ArgoCD применяет изменения, Kubernetes выполняет rolling update.
  4. Health checks проверяют работоспособность новых подов.
  5. В случае ошибки автоматический откат (настроено через `rollback` в ArgoCD).

== 2. Окружения

[cols="1,3,3", options="header"]
|===
| Окружение | Назначение | Способ развертывания
| **dev** | Разработка и unit-тесты | Локальный minikube или кластер в облаке. Обновления по pull request.
| **staging** | Интеграционное тестирование, нагрузочные тесты | Полный аналог production. Развертывается из ветки `main` автоматически.
| **production** | Боевая среда | Развертывание из тега (release). Требует подтверждения. Используется blue/green для критичных сервисов.
|===

== 3. Контейнеризация и управление образами

* Все сервисы упакованы в **Docker** с минимальными базовыми образами (Alpine, Distroless).
* **Dockerfile** содержит многостадийную сборку, чтобы уменьшить размер финального образа.
* Образы хранятся в приватном реестре **GHCR**, настроено сканирование уязвимостей.
* Для безопасности образы подписываются (cosign) и проверяются при развертывании.
